# Планирование закупок: демо

Демо системы планирования закупок для импортёра инструмента и оборудования с плечом поставки 4–6 месяцев. На входе шесть CSV-выгрузок ERP из `share/`, на выходе план закупок на 791 позицию с объяснением каждого решения. Весь расчёт идёт в браузере, в файле `dashboard/engine.js`: без сервера, без сборки, без API.

**Открыть в браузере:** https://kucuruza.github.io/test-velsa/

## Как открыть локально

Скачайте репозиторий (Code → Download ZIP), распакуйте и дважды щёлкните `dashboard/index.html`. Интернет нужен только для шрифта и графиков (Chart.js). Без сети вместо графиков будет подпись, расчёт работает.

## Вход

`share/`: `sku_dim.csv` (791 позиция), `sales_monthly.csv` (37 414 строк, 11.2020–08.2026; неполный август 2026 в историю не входит, только в остаток «сегодня»), `stock_monthly.csv`, `purchase_orders.csv` (660 заказов поставщикам), `receipts.csv`, `supplier_dim.csv`. Встроенный снимок этих файлов — `dashboard/data.js`. «Сегодня» = 13.08.2026, дата выгрузки.

## Что происходит по шагам (`engine.js`)

1. `parseCSV` → `ingest` — разбор шести файлов и проверка колонок (ошибка называет файл и колонку), компактный снимок.
2. `run` — расчёт по каждой позиции:
   - чистый спрос (продажи минус возвраты) и восстановление упущенного спроса в месяцах без остатка — `restore`;
   - сезонный индекс категории и тип спроса по данным (сезонная, умеренная, ровная) — `catSI`;
   - поставщики: доля поставки (fill rate) по сверке заказов с приходами и по полю ERP, плечо (медиана и p90), блокировка поставщиков, которые не отгружают, — `supplierStats`;
   - открытые заказы: ожидаемый приход = в пути × доля поставки; просроченные без подтверждения — 0 — `openArrivals`;
   - дневная проекция остатка на 18 месяцев, страховой запас, «хватит до», «заказать до», срок к сезону, количество на окно [приход; приход + цикл + покрытие], статус — `decide`;
   - основание и объяснение каждого решения по коду причины — `texts`; альтернативный поставщик — `altFor`;
   - итоги: план по поставщикам, ключевые показатели, сигналы, готовность к сезонам, семь ловушек данных.
3. `selftest` — 31 проверка: счётчики из README данных, суммы, арифметика количества по всем 791 позициям, эталоны.
4. `diff` — «Что изменилось» между двумя прогонами.

## Параметры

Окно «Пересчитать» в шапке: покрытие после прихода (90 дн), цикл заказа (30), минимальная наценка (25 %), порог избытка (18 мес), уровень сервиса A/B/C (90/85/80 %), буфер к сроку (14 дн), метод доли поставки (по приходам или по полю ERP), компенсация доли поставки в количестве (выкл.), порог потерь для «Просрочено», порог «хвоста C». Значения проверяются: если параметр выходит за допустимый диапазон, ядро ставит ближайшее допустимое значение.

## Выход

- план «Сейчас» по поставщикам, статус и основание у каждой позиции;
- карточка позиции с разбором «откуда количество»;
- сводная таблица: 27 показателей, группировка по категории, поставщику, статусу или классу с итогами;
- CSV плана и заказов (для Excel: BOM, разделитель «;»);
- «Данные и проверки»: семь ловушек данных → правило → сколько позиций задето, сверка с README данных, самопроверка, время прогона.

## Что посчитано, а что заготовлено

Посчитано ядром: каждое число и каждая фраза с числом на экранах; сценарии «Заполнить сезон», «Добить контейнер», «Ликвидация», «Пересмотр цены», «Надёжность»; перенос на альтернативного поставщика.

Заготовлено:
- панель агента — муляж: ответы собраны шаблонами из данных прогона, без модели и сети (живой агент — фаза 2);
- названия позиций и поставщиков условные, коды — из данных;
- эластичность спроса в «Пересмотре цены» — допущение.

Денег в расчёте нет: закупочных цен в выгрузке нет.

## Повторяемый запуск

Раз в цикл (30 дней) после выгрузки ERP:

1. Сохранить шесть свежих CSV.
2. В дашборде нажать «Пересчитать».
3. Перетащить файлы в зону «Перетащите шесть CSV сюда» (или нажать на неё и выбрать) → «Запустить».
4. Проверить «Что изменилось» и «Данные и проверки».
5. «Сформировать заказы» — CSV по поставщикам.

## Как пересобрать `data.js`

В дашборде: «Пересчитать» → загрузить шесть CSV → «Запустить» → «Сохранить снимок данных (data.js)» → положить файл в `dashboard/`.

Или из корня репозитория одной командой (Node.js 18+):

```
node -e "const E=require('./dashboard/engine.js'),fs=require('fs'),t={};['sku_dim','sales_monthly','stock_monthly','purchase_orders','receipts','supplier_dim'].forEach(n=>t[n]=fs.readFileSync('share/'+n+'.csv','utf8'));fs.writeFileSync('dashboard/data.js',E.snapshotJs(E.ingest(t)))"
```

## Три команды проверки чисел

Из корня репозитория.

1. Самопроверка ядра и время прогона. Ожидается `31/31`; время зависит от машины (100–300 мс):
```
node -e "const E=require('./dashboard/engine.js'),fs=require('fs'),C=E.loadSnapshot(fs.readFileSync('dashboard/data.js','utf8')),R=E.run(C),T=E.selftest(R,C);T.filter(t=>!t.ok).forEach(t=>console.log('FAIL',t.name));console.log(T.filter(t=>t.ok).length+'/'+T.length,'run',Math.round(R.timing.total),'ms')"
```
2. Итоги плана — те же числа, что на главной: «Заказать сейчас» 165 поз. / 103 265 шт, «Сменить поставщика» 74, готовность обогревателей 82 %:
```
node -e "const E=require('./dashboard/engine.js'),fs=require('fs'),R=E.run(E.loadSnapshot(fs.readFileSync('dashboard/data.js','utf8')));console.log('план',R.plan.now.count,'поз.',R.plan.now.qty,'шт; сменить поставщика',R.statusCounts.blocked,'; низкая наценка',R.statusCounts.margin);R.seasonReadiness.forEach(r=>console.log(r.title,r.season,Math.round(r.readiness.transitOnly*100)+'% до заказа,',Math.round(r.readiness.planFill*100)+'% с планом × доля поставки'))"
```
3. Сырые CSV без ядра против снимка: сумма `on_order_qty` из `sku_dim.csv` равна сумме «в пути» по открытым заказам (20 039), и расчёт по `share/*.csv` совпадает со встроенным `data.js`:
```
node -e "const fs=require('fs'),E=require('./dashboard/engine.js'),L=fs.readFileSync('share/sku_dim.csv','utf8').trim().split(/\r?\n/),h=L[0].split(','),k=h.indexOf('on_order_qty');console.log('on_order_qty из CSV:',L.slice(1).reduce((a,l)=>a+(+l.split(',')[k]||0),0));const t={};['sku_dim','sales_monthly','stock_monthly','purchase_orders','receipts','supplier_dim'].forEach(n=>t[n]=fs.readFileSync('share/'+n+'.csv','utf8'));const a=E.run(E.ingest(t)),b=E.run(E.loadSnapshot(fs.readFileSync('dashboard/data.js','utf8')));console.log('в пути по PO:',a.checks.pendingOpen,'; CSV = снимок:',E.stableJSON(a)===E.stableJSON(b))"
```

Те же проверки есть в интерфейсе: «Данные на 13.08.2026» в шапке → «Данные и проверки».

## Где что лежит

- `dashboard/` — дашборд: `engine.js` (расчёт), `data.js` (снимок CSV), `app.js`, `app.css`, `index.html`, `agent-mock.js` (шаблоны ответов агента), `icons.js` (иконки lucide).
- `share/` — исходные CSV и описание данных.
